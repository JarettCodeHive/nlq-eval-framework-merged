# Client Progress Updates

Dated snapshots of the client-facing progress deck, one file per update —
each is a point-in-time record, not something later updates overwrite.

Naming convention: `client_progress_update_YYYY_MM_DD.pptx`, dated to the
day the deck was sent, so filenames sort chronologically.

| Date | File |
|---|---|
| 2026-10-20 | [`client_progress_update_2026_10_20.pptx`](client_progress_update_2026_10_20.pptx) |

Each deck is edited directly (there's no template/generator for it) — when
the codebase moves on (a flag renames, a stage's behavior changes, a status
goes from "in testing" to "validated"), check the most recent deck's
pipeline-execution and progress slides against current behavior before
sending it again, the same way this one was brought current from the
06-Oct-2026 version it replaced.
