# CRM Q&A Taxonomy Spec (POC)

Status: DRAFT — pending OI-1 (T1 single-table tier), OI-2 (numeric
equality), OI-4 (NULL ingestion). T1 content is generated but **held**
per Risk R-10 until OI-1 is confirmed. T3 content is **held** on OI-4.

Source of truth: `NLQ_Evaluation_Framework_Execution_Scope_updated.pdf`
Sections 6-9, 23. This spec maps the fixed T1-T5 tiers (Section 9.2) onto
the `crm_dataset_v2` schema. It does not redefine the tiers.

## 1. Scope

CRM tables (`schema/ddl.sql`): `accounts`, `contacts`, `campaigns`,
`contact_campaigns` (contacts<->campaigns many-to-many bridge),
`interactions`, `support_cases`. CRM covers customer engagement, campaign
attribution, and support-case / SLA behaviour. No sales pipeline or
revenue (that is the Sales domain). USD only. `reference_today` =
`2026-08-01`; "last quarter" = Q2 2026 (`2026-04-01` .. `2026-07-01`),
"this quarter" = Q3 2026 (`2026-07-01` .. `2026-10-01`).

Declared join paths: `crm_allowed_join_paths.csv` (JP1-JP12). No family
may use a join outside this list (Section 8.2 shortcut prevention).

## 2. Quota (Section 9.1)

T1=32, T2=40, T3=32, T4=32, T5=24, total=160, across 28 families
(`crm_question_family_matrix.csv`). Families deliberately over-provide
distinct parameter values; `scale_pairs.py` consumes families in id order
and stops each tier at its Section 9.1 quota, so the shipped set is
exactly 32/40/32/32/24.

## 3. Tier-by-tier

- **T1 (32) — HELD (OI-1).** Six families: campaign budget by type,
  campaign count by status, case count by priority / category,
  interaction count by engagement type, account count by region. Fully
  generated by `scale_pairs.py` into `crm_t1_pairs_HELD.csv` but not
  shipped until OI-1 resolves. If T1 is dropped, the 32-pair quota is
  redistributed into T2-T5.
- **T2 (40) — clear to ship.** Seven families over JP1/JP4/JP5/JP6/JP7.
  Largest tier, so families vary the *filter value* across their pairs,
  not just the grouping label. Fully generated into `crm_t2_pairs.csv`.
- **T3 (32) — HELD (OI-4).** Six missing-relationship families. Every T3
  `expected_answer` assumes Pulse ingests an empty CSV field as NULL; if
  it is read as an empty string these answers must be re-verified
  against Pulse's own join behaviour. Section 7.6 gate: the dataset
  validator already confirms each LEFT path has unmatched parent rows.
  POC ships one hand-written seed per family only.
- **T4 (32) — clear to ship.** Five families over the 3-hop chains
  JP9/JP10/JP11. POC ships hand-written seeds for T4-01/02/03.
- **T5 (24) — clear to ship.** Five families: top-N rankings, open
  backlog, composite at-risk logic, quarter-over-quarter change, regional
  growth. Every T5 pair has a deterministic numeric core computed by one
  SQL query (Section 9.2: "T5 is not a harder SQL tier"). POC ships all
  five seeds.

## 4. Answer format

`crm_answer_format_matrix.csv`. Numeric default follows Section 8.1
(period decimal, no thousands separator) pending OI-2 confirming it
applies to `expected_answer` strings specifically.

## 5. Edge-case coverage

`crm_edge_case_coverage_map.csv` maps every Section 7.5 imperfection
(near-duplicates, missing values, outliers, boundary dates) and the
Section 7.6 missing-relationship scenarios to at least one family.

## 6. What this spec does not do

It does not author the full 160 pairs, and it does not resolve OI-1/OI-2/
OI-4. It does not redefine T1-T5.
